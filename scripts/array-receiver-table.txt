# scripts/array-receiver-table.txt — the canonical row source for the
# ADR-0004 node-differential table.
#
# FORMAT (one directive per line, `#` starts a comment, blank lines ignored)
#
#   receiver <name>
#   decl     <expression that evaluates to the receiver>
#   method   <method-name> <call expression, in terms of `o`>
#
# Everything else about a row — the observation harness, the JSON of the
# generated Rust, the `expected` values — is DERIVED by
# scripts/gen-array-receiver-table.py. `expected` is whatever `node` printed
# for the generated program, so regenerating is a command, not a transcription.
#
# WHY THE RECEIVERS ARE NINE. ADR-0004's table was measured on ONE receiver
# (`{0:"a",1:"b",2:"c",length:3}`) and generalised from it to "17 of 24
# methods diverge". That is the claim this table exists to make checkable:
# every receiver below is a distinct rung of `LengthOfArrayLike` +
# `HasProperty`/`Get`/`Set`, and a method that is right on one is still wrong
# on another. `sparse_ctor` and `length_assigned` are deliberately redundant
# — `new Array(3)` and `[]; o.length = 3` reach the same declared length by
# different constructors, and Batch 2's `store_shape_extension` fix touched
# exactly that construction.
# The last four rows are NOT Array.prototype methods and they are the four
# most important rows in the file. They exist because Batch 1's table marked
# the sparse receivers as matching `node` while `new Array(3)` followed by
# `a[0] = "z"` reported `length` 1 where node reports 3 — and every row the
# table actually contained was a METHOD call, which either writes every index
# (`fill`, `copyWithin`) or goes through `set_array_len` (`push`, `pop`,
# `splice`), so nothing in it could ever observe a partial index write below a
# declared length. `ArraySetLength` is reachable only by writing one index.
# A table that cannot see the bug it is cited for is the same failure as a
# transcribed one, one level up.
#
# WHY THERE ARE NOW SIXTEEN (Batch 6). Nine of these receivers were selected
# before anyone wrote down which decision points the 39 methods actually branch
# on, and the list has three gaps a reader can see from the code:
#
#   1. **No hole strictly below the visible extent on a non-`Array`.**
#      `visible_extent` (`builtins/array.rs`) returns ONE PAST the highest
#      integer key reachable on the receiver or its prototype chain, and
#      `read_slots` short-circuits every index `>= extent` to "hole" without
#      dispatching. Every pre-Batch-6 receiver either has a contiguous index
#      range (`own_*`, `array_dense`) or a visible extent of 0/1
#      (`inherited_*`), so `index_get`'s presence branch only ever ran where
#      the answer was `present == true`. `holey_object` below is the smallest
#      receiver that reaches it with `present == false`.
#   2. **No receiver where a `[[Get]]` must invoke an accessor.** Both the
#      length read (`array_like_len`) and the index read (`index_get`) route
#      through `dispatch_get`, which is the only thing that makes a getter a
#      getter; a shape-slot read would answer a plain value and no row would
#      notice. `accessor_index` (getter AT an index) and `length_getter`
#      (getter AS the length) pin the two call sites separately, because they
#      are two call sites.
#   3. **No receiver where an own index SHADOWS an inherited one, and none
#      where the chain is deeper than one hop.** `inherited_indices` has no own
#      properties at all, so "own wins over inherited" is never decided by a
#      row; and a reader that walked exactly one prototype hop would score
#      identically on every pre-Batch-6 receiver, because all of them are at
#      most one hop deep. `shadowed_index` and `proto_chain_two_deep` are those
#      two rungs.
#
# `length_float` and `length_negative` are the two `ToLength` outcomes no
# earlier receiver reached: truncation (`3.7` → 3) and the clamp of a negative
# to zero. `own_string_length` covers coercion, not either of these.
#
# NOT COVERED, DELIBERATELY: a **Proxy** receiver. `index_get`/`index_set` reach
# `proxy_get`/`proxy_set`, which are the unimplemented-trap stubs and throw
# `TypeError`; a Proxy row would measure the stub, not the index/length model,
# and would belong in the `absent` ledger as a separate entry rather than
# inflating this table's denominator with rows whose expectation is "it threw".
